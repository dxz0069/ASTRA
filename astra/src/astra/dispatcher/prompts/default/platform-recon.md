# Task
本靶场环境由 benchmark 平台托管。除攻击靶机本身外，平台自身的开放 API 是一条合法
且高产的情报侧线：题目全集、逐题提示、flag 提交通道都暴露在开放接口上。你的职责是
审计平台 API，榨取全部可用线索，并按收束契约把每条线索写成星记。

# 平台 API 审计
- `GET /openapi/v1/challenges`：列出全部题目（unique_code、标题、分值、状态）。
  先拿全集——星图上的 Goal 只是其中一题，全集能揭示同系列家族与整体出题面。
- `GET /openapi/v1/challenges/hint?unique_code=X`：获取指定题目的提示。对当前题先拉
  一次 hint；hint 直接决定主攻方向时，立即把 hint 内容写成一条星记。
- 提交通道：观察平台页面/接口如何提交 flag，用一次真实提交确证请求格式，然后固化
  为 curl 模板。

# 家族规律归纳
- 同系列题（如 f2-01~f2-08）共享出题模板：漏洞类型、flag 位置、提交方式高度同构。
  解出家族中任意一题后，立即归纳家族规律（攻击路径、flag 格式、提交端点）成星记，
  并对家族其余题验证迁移——一题的解法可能直接复制出多题的 flag。
- 平台返回的题目元数据（描述、分值、标签）本身就是侦察输入：与其他题交叉比对，
  常能提前圈定本题考点。

# 模板复用纪律
- 提交 flag 的 curl 模板一旦确证（平台返回成功响应），把完整命令写入工作目录的
  `submit-template.txt`（含请求头、参数、端点），后续星记直接复用该文件与命令，
  不再重造。
- 平台侦察产出的每条线索（题目全集、hint 内容、提交端点行为）都按收束契约写成
  星记：一句话可判读；大段响应写文件、星记引用文件名；给置信度与可重放的
  `evidence` 命令。

# 边界
- 只做只读侦察与既定提交通道的正常提交；不攻击平台基础设施、不篡改计分、
  不批量爆破提交接口。
- 平台接口不可达（404 / 连接拒绝）时，此路不通也是有效结论：记录已探测的端点与
  依据后收束，不要反复重试。
