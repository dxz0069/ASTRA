## 第一部分：PDF 方案学习与"改好适用"

### 1.1 原方案是什么

PDF 的四层架构（技术栈 Redis + FAISS + Neo4j + LangChain + gpt-3.5）：

| 层 | 心理学模型 | 原实现 | 作用 |
|---|---|---|---|
| L1 瞬时感官记忆 | Atkinson-Shiffrin | Redis list，8000 token 上限，超限丢弃旧 40% | 原始信息缓冲 |
| L2 工作记忆 | Baddeley | 文本环路/视空画板/情景缓冲，LLM 融合摘要 | 实时上下文管控 |
| L3 短时向量记忆 | 多存储模型 | FAISS 向量库，7 天过期 | 相似度召回 |
| L4 长时图谱记忆 | 海马巩固 + 联结主义 | 每日定时 LLM 蒸馏 → (实体,关系,实体) 三元组 → Neo4j | 永久结构化存储 |

外加三个进化机制：回忆强化（调取后重新摘要入库）、艾宾浩斯遗忘权重、按用户分片。

**客观评价**：概念框架是好的，代码是教程级的（无并发保护、FAISS 删不掉已入库向量、Neo4j Cypher 字符串拼接注入、蒸馏线程无错误处理）。**不要照搬代码，要搬走思想。**

### 1.2 关键洞察：ASTRA 其实已经有四层记忆的"骨架"

对照现有代码，四层模型与 ASTRA 现状惊人地同构，只是缺少"越用越好用"的闭环：

| 四层模型 | ASTRA 现有对应 | 现状差距 |
|---|---|---|
| L1 瞬时记忆 | worker CLI 的会话上下文（dsh/claudecode 内部） | 无深浅分级：闲聊级输出与关键发现同等对待，靠 token 预算硬裁 |
| L2 工作记忆 | `dispatcher/context.py` 的 focus 构建（相关性打分 + 预算裁剪 + graph.yaml 引用） | 已相当好；缺"情景缓冲"式的跨题态势融合 |
| L3 短时记忆 | 星图 Fact 库（SQLite）+ consolidate/Epitome 摘要压缩 | **无语义召回**——只有 token 重叠打分（`_relevance_score`），"SQL 注入的教训"召回不了 "MySQL 注入" |
| L4 长时记忆 | `container/knowledge/challenge-approaches.md` + AGENTS.md 题型模式库（人工合并） | **闭环断在人工**——解出题自动挖掘到 /tmp JSON 后要人合并；无遗忘/强化权重 |

所以升级不是"新增一个记忆系统"，而是**给已有的四层补上：语义召回（L3）+ 自动固化闭环（L4）+ 强化与遗忘（进化机制）**。

### 1.3 适配设计（改好适用版）

原则：不引入 Redis/Neo4j 重中间件（容器内已有 SQLite + markdown 体系，评测环境装 Neo4j 是负担）；不用 langchain；嵌入模型用本地小模型或 API。

**L1 加深浅分级（低成本，先做）**
- worker 产出的星记写入时增加 `depth` 字段（flag/凭据/关键路径 = deep；普通探测记录 = shallow）。
- 落点：`server/services.py:create_fact` 加可选参数；写入方在 `dispatcher/tasks/` 各任务的 prompt 中要求标注。focus 构建时 shallow 事实只留一行索引，deep 事实全量内联——把现有 token 预算花在刀刃上。

**L3 语义召回（核心增量）**
- 给 Fact 加 `embedding` 列（sqlite-vec 或直接 numpy 余弦，量级 <1e4 不需要 FAISS）。
- `context.py:_relevance_score` 升级为 `0.5×token重叠 + 0.5×向量相似`，接口不变。
- 嵌入来源：智谱 embedding API（已有 key）或容器内 `all-MiniLM-L6-v2`（中文题面建议 bge-small-zh）。启动时懒加载，无嵌入时降级为纯 token 打分——**零风险回退路径**。

**L4 自动固化（把人工合并环节自动化）**
- 现有 `/tmp/astra-knowledge-append.json` 追加文件，改为赛后由一个离线脚本自动执行：去重（与已有条目做向量相似度 ≥0.9 判重）→ 按题型归类 → 追加进 challenge-approaches.md。
- 进一步：把"攻击链三元组"（入口类型 → 漏洞类别 → 利用方式）结构化存进 knowledge/attack-graph.yaml，新题开局注入时按题型匹配相关子图，而不是整库注入。

**进化机制（"越用越好用"的三件事）**
1. **回忆强化**：某条知识条目被注入且该题解出 → 该条 `hit_count+1`、更新 `last_used`；注入了但题没解出且走弯路 → 不惩罚但记录 miss（供人工复盘）。
2. **遗忘曲线**：开局注入时按 `score = hit_count × recency_decay(last_used)` 排序，预算内只注入高分条目——知识库自动向"高频有效打法"收敛，低效老条目自然沉底。
3. **复盘生成器**：每轮赛后用一个轻量 LLM 任务把本轮全部星图浓缩成"新题型条目 + 旧条目修正建议"草稿，人只做审核（保留 human-in-the-loop，但成本从"读原始日志合并"降到"审核草稿"）。

**实施顺序建议**（每步独立可回退）：L4 自动固化脚本（纯离线，最安全）→ L1 depth 字段 → L3 语义召回 → 强化/遗忘权重 → 复盘生成器。

## 第二部分：广泛调研与客观建议

### 2.1 同类产品格局

**AI 记忆系统赛道**（2026 现状：无一家通吃）
- **Mem0**：往现有 stack 外挂记忆，快速集成路线，开源可自托管；
- **Zep / Graphiti**：时序知识图谱路线（Graphiti 引擎 Apache 2.0），强在大规模实体演化，但依赖图数据库；
- **Letta（MemGPT 后继）**：**自管记忆**路线——agent 自己通过工具操作 Core/Recall/Archival 三层记忆，最接近"自进化"理念；
- 另有 LangMem、Cognee、Supermemory 等十余家。社区共识："Mem0 起步快，Zep 规模大，Letta 自治强"。

**对 ASTRA 的启示**：Letta 的"agent 自管记忆"与你们的 consolidate 任务（自动压缩星图）方向一致，说明路线选对了；Zep 的时序知识图谱是 L4 攻击链图谱的直接参照物。

**自主渗透 Agent 赛道**
- **XBOW**：HackerOne 全球榜首（1060+ 有效提交），近零误报，商业标杆；
- **CAI（Meta 开源）**：开源框架中引用最多，benchmark 常客；
- **Simbian / Escape / NodeZero(Horizon3) / Corgea**：分别在持续渗透、API 测试、内网 AD、报告生成上各占一角；
- 已有独立开发者用本地 agent 在 XBOW benchmark 上打到 78%——说明**开源/自建 agent 与商业方案差距在缩小**，ASTRA 走的路有天花板。

### 2.2 可发展方向（按与现有资产的匹配度排序）

1. **"经验复利型安全 Agent"作为核心卖点（最推荐）**。市面上所有竞品（含 XBOW）的记忆基本是静态知识注入；ASTRA 已有星图 + 自动挖掘 + 知识库闭环的独特地基。把第一部分的强化/遗忘/自动固化做实，就能讲一个竞品讲不出的故事："同一个 agent，第 100 道题比第 1 道题强"。这也是西湖论剑/BSRC 演示叙事的最佳素材（机制性演示，符合"去战绩化"要求）。
2. **赛后复盘报告产品化**。渗透测试的付费痛点不是 flag 是报告。ASTRA 星图天然是证据链（发现→验证→利用），加一个 report 任务类型把星图渲染成中文渗透报告，直接对齐甲方交付物——这是比刷榜更可持续的价值。
3. **多机协同/横向内网**。NodeZero 占住的内网 AD 场景国内需求大；星图的多项目结构（Project/Fact/Intent）天然适合"打点后横向"的状态管理，属于架构顺延而非重构。

### 2.3 可优化改进方向（工程层）

- **召回质量**：L3 语义召回（见 1.3）是当前性价比最高的单项改进；
- **闭环自动化**：/tmp JSON → 人工合并 是全链路唯一的人工堵点；
- **评测维度**：给知识库条目建立 hit/miss 统计后，可以量化"记忆带来的分数增益"（同一题关/开知识库对比），这是所有演示里最有说服力的数字；
- **技能库增长**：目前靠人工 + vendoring，可让赛后复盘生成器顺带产出"值得沉淀为 SKILL.md 的打法"草稿（参考 Voyager 的 skill library 思路），仍人审。

### 2.4 如何"彻底变得不像 Cairn"

现状评估：README 已重写为 ASTRA 星辰叙事，核心协议（Stellar/Bearing/Guidance、dispatcher、星图）是自己的设计；**但目录名 Cairn-main、astra 包内的模块划分和 docs/specs 仍带上游影子**。彻底切割建议：

1. **仓库/包名**：rename 为 astra 顶层仓库（或新 org），删掉 Cairn 字样的残留引用（`grep -ri cairn` 清零）；
2. **记忆系统是最大差异化资产**：四层记忆 + 经验复利做成对外可见的产品特性（文档、CLI 子命令如 `astra memory stats`），这是上游没有的身份标识；
3. **叙事重心**：对外定位从"调度框架"换成"会成长的安全 Agent"——框架是管道，记忆是灵魂，管道不值钱灵魂值钱；
4. **license/合规**：确认上游 Cairn 的 license 要求（保留版权声明或获得授权），避免比赛/商用阶段的法务隐患。

### 2.5 一句话结论

你们和 PDF 方案的关系是"殊途同构，各缺半边"：PDF 有四层理论但代码玩具化，ASTRA 有工业级四层骨架但闭环断在人工。**不搬 PDF 的代码，搬它的三个思想——语义召回、自动固化、遗忘/强化——落到已有的星图 + 知识库上，ASTRA 就从"跑一次强一次"的手调系统，变成"每跑一次自动变强"的进化系统。**
