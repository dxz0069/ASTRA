> 2026-08-29。前提：v0.2 FGS 重建完成（星图协议 + 定航/巡猎双活动 + pi 底座 + 赛制经济层）。
> 评估框架：每项 = 价值（对平台定位/得分/论文）× 成本 × 依赖；排序即建议实施序。
> 纪律：一次只动一层；打分管线（pi spike→镜像→打包→托管轮）优先于一切拓展。

## 二、逐项评估

### 1. SRC/众测适配器（最高优先——平台定位的兑现）

**是什么**：runner 适配层的第二个实现（照 `tsecbench_adapter.py` 范式）。靶场适配器产出 flag；SRC 适配器产出**客星（Finding）报告**——
目标列表来自众测平台 API 或手工导入，产出按平台要求格式化（漏洞标题/等级/PoC/复现步骤/修复建议），
人工确认后提交。

**为什么是它**：v0.2 的 Finding 模型就是为此而生（"搜索的产出是沿途的漏洞而非终点"）——
协议层零改动，只写一个新 runner 适配器 + 报告模板。这也是"通用平台"定位的第一个非 CTF 实证，
答辩/论文的核心场景（星辉计分模型直接对标真实交付物）。

**要点**：授权边界模块（目标白名单/范围校验）必须先行；人工审核闸门默认开（SRC 合规）。

### 2. 代码审计模式

`origin=仓库路径，北辰=审计覆盖（如"全部危险函数面已核"）`——巡猎者用 read/grep/semgrep 类工具
读码，星辉=发现的漏洞（带文件:行号），星图天然支持"覆盖型北辰"（子方向逐项结论齐即达成）。
与 SRC 适配器共享报告出口；也是"通用任务求解引擎"的又一实证。

### 3. 星座层：跨项目星记共享

同网段多题场景下，A 题侦察出的主机/端口/凭据星记自动对 B 题可见（星图 schema 天然支持，
只差一个共享层与相关性路由）。Tsecbench 同族题（f2-01~08）是现成试验场；
风险是污染（跨题错误传导）——按相关性分数+人工开关控制。论文对应 CTFExplorer 多目标范式。

### 4. CLI 单任务模式

`astra solve "拿到 http://x 的 flag"` 一条命令本地起星图跑完——演示/答辩/日常使用的门面。
local 模式已有，只缺 CLI 包装（serve+dispatch 内存起 + 单项目 + 结果打印）。

### 5. 标准报告出口

星辉→SARIF 2.1（业界扫描器标准）/自有 JSON Schema；报告生成器已是星辉版，加导出格式即可。
SRC 适配器与企业集成（CI/CD）的前置。

### 6. 四层记忆系统

方案已定稿（docs/四层记忆系统升级方案与调研.md）。v0.2 后的地基更干净：星图=事实层已 append-only，
记忆系统叠加的是**跨 run 复利层**（经验蒸馏/召回/遗忘）。论文主贡献（经验复利型安全 Agent），
1-2 周量级，排在赛事后。

### 7. Local 模型底座

pi 直连 Ollama/vLLM 端点（models.json 已支持任意 baseUrl）——成本趋零的长尾题执行器。
榜首在押注本地模型（"渗透一个网站成本以分计"）；我们观察其成熟度，工具面已就绪。

### 8. 实时观测出口

runner 状态 webhook（进度/星辉/告警推外部）——团队协作场景用，按需。

## 三、不做清单（与路线冲突，防走回头路）

- 审查环/置信度体系回归（体检表已裁决：错交免费下期望收益为负）
- 记忆压缩机械回归（append-only + 焦点裁剪已覆盖）
- MCP 工具动物园（Meta-Tooling 纪律：给巡猎者更好的原料，不加包装工具）
- 角色子智能体（并发≠分工）
