## 1. 一句话定位

**ASTRA（星辰）是一个面向 AI 攻防全链路的星图导航引擎**：给定起点（靶场地址/目标系统）与目标（获取 flag/定位漏洞），在未知状态空间中做有向搜索。它不定义角色、不预设工作流、不内置安全任务知识——任务知识只存在于任务描述层，引擎是通用搜索机。AI 漏洞挖掘与渗透测试是它的第一片已证明的星域（Tsecbench 63 题靶场，八轮真实平台实测）。

血统：fork 自开源黑板架构方案，经 v0.2 星图协议重建与 v0.3.0 星尘记忆满血两代重写，与上游分歧 288 文件（+73k/−17k 行），保留其"极简协议"血统，重写其执行底座与调度经济学。

## 2. 设计立场（三条公理）

1. **状态资产化**：世界状态是系统资产而非模型回忆——全部状态外部化为一张 append-only 因果图，图是唯一共享记忆；进程可死可换，上下文不腐烂。
2. **双活动，无角色**：引擎只有两类活动，它们是同一个运行器注入不同提示词与工具的实例，而非固定角色的子智能体。规划不执行、执行不规划，图的并发正确性由服务端租约保证。
3. **时间即预算**：在固定时间窗计分赛制下，吞吐即分数。调度决策（开题顺序/波次轮转/信息购买/进度保全）被显式建模为预算优化问题（论文 C1 核心）。

由此推出的"坚决不做"清单：无审查环、无记忆压缩器、无预设技能注入、无 Observer 旁路纠偏、无按角色分工的多智能体——每一项都有控制三分法（能力缺口加/信任缺失不加/经济性算账）的归类依据（`container/AGENTS.md` 体检表，论文 C2）。

## 3. 星图协议（状态层）

五原语、append-only、图即账本：

| 原语 | 语义 | 关键约束 |
|------|------|---------|
| **天枢（Fact）** | 一条已确认的客观发现（负结果同权） | 自证入图：跑过命令、亲眼看到输出才写回 |
| **北辰（Goal）** | 完成条件 = 搜索终止条件 | 判定权仅在玉衡 |
| **斗柄（Step）** | 从既有天枢出发、预期产出新天枢的因果行动 | 开必附 expect；关必留 close_reason（防重开死路） |
| **客星（Finding）** | 搜索沿途的不期产出（如漏洞） | 一等公民，随斗柄收束入图 |
| **辅星（Hint）** | 任意时刻注入的人类判断 | 星官下次读取时吸收；平台提示/运维提示/失败教训共用此原语 |

星官（Worker）命名取自北斗星官：**玉衡权衡定向，摇光出击巡天；沿途记天枢、偶见客星、辅星随行、逐宿而驻，终抵北辰。**

## 4. 双活动架构（行动层）

```
┌────────────────────────── 编排层（astra-runner）──────────────────────────┐
│ 开题排序(value-hybrid) → 波次调度(10min) → 回访预算(10波/旗数扩展)         │
│ 平台适配(tsecbench) → flag 提取/假旗过滤/大小写折叠去重 → 提交与回执入图    │
│ 自愈四层：网络退避重进 / close 清道夫 / 全停看门狗 / 半死看门狗(execv)      │
└──────────────┬────────────────────────────────────────────┬──────────────┘
               ▼                                            ▼
     ┌──────── 玉衡 Decide（串行/图事件触发）────────┐   ┌─── 摇光 Execute（并发多实例）───┐
     │ 干净上下文起跑；只拥有图操作权限：             │   │ 共享工作目录并行（文件礼仪协作）；│
     │ 判北辰/开斗柄(≤9)/关斗柄(留痕)/增删星宿       │   │ 世界工具 bash/read/write/edit； │
     │ 提示词 ~1.9KB：只判断两件事                   │   │ 恰好一条天枢收束；超时流式抢救   │
     └────────────────────┬────────────────────────┘   └──────────────┬───────────────┘
                          ▼                                           ▼
                   ┌──────────────── 星图（SQLite，服务端） ─────────────────┐
                   │ 原子认领/收束（守卫 UPDATE，TOCTOU 零窗口）· 租约心跳    │
                   │ · 过期回收 · Epitome 图压缩 · 质询星探(fail-open)      │
                   └────────────────────────────────────────────────────────┘
```

- **角宿（Bootstrap）**：项目启动的首次摇光，从起点直接开工，流式产出天枢。
- **执行底座 pi**（`@mariozechner/pi-coding-agent`，Node）：选它因为它最原始、完全可控——内置提示词极短且与安全任务零耦合。每实例独立会话目录，长会话病理（上下文腐烂）从底座上消除。
- **并发模型**：多星官 = 并发探索而非角色分工（论文 C4）。同图并发正确性由服务端守卫式原子操作保证（`claim/conclude/decide` 三族，WHERE 条件写入时重估）；星图是 stigmergy 信息素轨迹——defer 回队收割依赖且仅依赖图，不依赖任何会话记忆。

## 5. 调度经济学（控制层核心，论文 C1）

固定时间窗计分赛制（`Score = Σᵢ vᵢ·fᵢ(剩余时间)`）下，四机制显式建模为预算优化：

| 机制 | 形式化 | 实现 |
|------|--------|------|
| **开题顺序** | 期望得分排序的组合优化 | value-hybrid：easy 热身（分值降序）→ 全池分值降序（hard 大分题不饿死） |
| **波次轮转** | 期权价值保全 | 10 分钟波次窗；defer 保留星图回队；预算 `B = 10 + 2·旗数 + hard + 图深`（帽 16）——已证产出题优先续投资（MCTS exploit 同型） |
| **信息购买** | 带价信息的购买阈值 | hint 门控默认关闭（榜首对照实证：零 hint 拿 97.14）；启用时按波次窗比例缩放 + 同文本拒购 + 卡题信号门控 |
| **多旗收割** | 边际收益再投资 | 部分旗不关题、defer 回队续攻；引擎归航 0 旗也转 defer 不沉没 |
| **死图重置** | 信息的期权清算 | 仅当旗与图双零增长才清图重来（图增长判据防误清侦察资产） |
| **饥饿回灌** | 尾窗满载 | 队列空且剩余>15min 时按 EV（近失>有积累>高分值）无视上限重拉已弃题 |

**实证**（八轮真实平台纵向记录）：
- R8（6h 完整窗口，长窗制）：27 题/27 旗全对，awarded 7040——零崩溃零僵死，24 项审计修复全窗口验证。
- R9（波次制+零 hint+写时治理+6 副本）：**有效解题 4.2h 拿 26 题**（VPN 断链 2h20m 事故扣除后），单位时间效率较 R8 +50%；开题覆盖 23 题/首小时（R8 同期 8 题）；hint 51 次 28% 转化 → 0 次；错交 7 → 3（终局归因后理论归零）。
- 对照组（榜首闭源方案 run 12662，97.14 分/72 旗/62 题）：我们完成 1236 条会话日志全量拆解（96% 前缀缓存命中/68s 中位短会话/13-28 并发/86 次实例重启回访/b 系 160M token 投入），差距归因清晰（短会话节拍+写时治理两工程维度），R9/R10 改动即按此对齐。

## 6. 星尘记忆（经验复利系统，论文 C3 实施路线）

四层记忆 + 进化机制：

- **四层**：瞬时（会话原始上下文）→ 工作记忆（焦点子图裁剪，预算硬上限零膨胀）→ 短时（星图事实库 + Epitome 自动摘要：老旧脱链事实折叠为单行索引，凭据/旗级/负结果/因果骨架永不折叠）→ 长时（攻击链沉淀，双层脱敏——flag 值正则 + secret 语境掩码，开局注入）。
- **进化机制**：语义召回（词面+向量混合，SQLite 持久化）、回忆强化/遗忘曲线（战绩 × 半衰期 30 天：`score=(hits−misses)·0.5^(Δt/30)`）、举一反三（同题型按战绩加权注入）、**赛中实时复利**（解出即沉淀热加载——同一场比赛越打越强）、失败经验库（死路避坑：负记忆也是资产）、战绩淘汰（0 命中且 ≥6 未命中条目停注入——实证 f1-04 条目 0/24 仍全量注入为纯噪音）、赛后自动蒸馏（三件套草稿自动产出，人工只审核）。
- **质询星探**：decide 的归航收束与凭据/旗级关键事实须经独立对抗审查（uphold/refute）方可入图；fail-open 契约——质询故障绝不卡主链路。审计有界纪律：每题质询限额、队列满即丢弃、三层兜底全 fail-open。

## 7. 可靠性与安全（长跑高负载工程，29 项审计修复）

**自愈四层**（R5-R7 三轮事故实战淬炼）：网络瞬断退避重进（断网 50min 免疫）→ close 清道夫（泄漏容器周期补关）→ 全停看门狗（12min 无写入 os.execv 原位重启）→ 半死看门狗（星图 15min 零增长自重启）。启动期 VPN 等待重试（30s×240，断链不再进程即死）；僵尸槽启动全量回收（换血后在跑容器占名额的自旋根治）；靶机地址漂移守卫（回访自动注入新地址）。

**安全面**（暴露为网络服务的完整威胁模型，13-35 轮审计）：
- 认证：`ASTRA_AUTH_TOKEN` 常数时间比较；中间件最外层（未认证请求不消耗 body 读取资源）；非回环绑定无 token 拒启动。
- 输入不信任：全请求模型字段帽（title 512/描述 65K/hints 200 条）；413 大图双格式导出防护；畸形 Content-Length 400；chunked 绕过封堵（有界读入缓存）；流式天枢 64 条帽（万行倾倒防护）；解析器资源边界（头/尾双窗口 + 起点封顶 + RecursionError 契约）。
- 数据完整性：服务端守卫式原子操作族（TOCTOU 零窗口）；赛中沉淀三写入器锁 + 临时文件原子替换；知识合并工具原子写；CSP 三档（UI 最小集/静态无/API `default-src 'none'`）；前端 x-text-only（零 x-html）+ 逃逸全覆盖。
- 旗完整性：假旗过滤三重（占位符/掩码标记/纯符号内容）+ 批内大小写折叠去重 + 省略号截断拒收 + 变体重试已移除（V2-3 考古归因）。

**测试**：237 项全绿（含 12 线程并发实证、真孙进程树杀实证、1.6MB 解析炸弹性能回归、品牌词表锁）。

## 8. 工程形态

```
astra/                    引擎（Python 3.12，FastAPI + 自研调度器）
  ├─ server/    星图服务（REST API、原子操作、Epitome、质询）
  ├─ dispatcher/ 调度器（双活动任务、pi 适配器、焦点上下文、提示词模板）
  └─ distill.py 赛后蒸馏
container/                容器与编排
  ├─ astra_runner/ 编排器（调度经济学、自愈、记忆管线、平台适配）
  ├─ Dockerfile.slim → astra-flat:v9（OCI 2.77GiB）
  ├─ .agents/skills/ 25 本题型打法书（bctf 血统，按题型注入）
  └─ AGENTS.md      执行环境协作规则 + 控制三分法体检表
```

部署双模式：**本地**（venv 直跑，调试/调参）与**托管**（平台起容器后注入凭证；runner 凭证等待循环 900s 不秒退；env 模板 `dist/hosted_v9_final.env`）。资源画像：6 执行副本×3 并发 + 1 决策 = 20 路并发星官；单通道 DeepSeek-flash（榜首实证吞吐 > 模型智商）；24h 窗口 token 消耗 ~33M 级（缓存命中率计量已埋，r10 首测）。

## 9. 与榜首闭源方案的差异化（论文定位护城河）

我们与榜首同构于：极简图协议、双活动、纯 flash、短会话化路线。**我们独有而榜首没有的**：
1. **跨轮记忆系统**（榜首跨 run 图重置只能靠 workspace 文件考古——四层记忆恰好补此洞）；
2. **对抗审查**（质询星探——榜首无任何审查机制）；
3. **显式调度经济学**（四机制形式化可消融——榜首是隐式工程调参）；
4. **29 项公开可复现的可靠性/安全审计链**（237 测试 + 八轮实测事故档案）。

榜首独有而我们的追赶项（诚实清单）：写时治理的提示词纪律成熟度、68s 中位短会话节拍、96% 前缀缓存命中。R9 已对齐方向（写时治理提示词重写/300s 步长/零 hint/波次制），差距量化见 §5 实证。
