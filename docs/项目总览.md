# ASTRA·星辰 项目总览

> 更新：2026-08-25 ｜ 本文档是项目的单一入口：定位、架构、版本演进、运维体系、产物清单。

## 一、定位

**经验复利型自主安全智能体**。核心命题：让安全 Agent 拥有记忆、越用越强——正面经验给方向、失败经验防重蹈、赛中实时生长、赛后自动结晶。区别于"更强单次执行"路线（学界已证其架构随模型升级而收敛），ASTRA 押注模型不会自己变强的能力：记忆、验证、调度、经验复利。

├────────────────────────────────────────────────────┤

## 五、运行形态

- **本地模式**：`dist/local.env`（token/密钥/舰队配置）+ `astra/.venv` 起 runner，状态板 `py -3 tools/run_status.py`；重启 SOP 见作战记录。
- **托管模式**：镜像 `agent-slim-v3.tar.gz`（2.8G，sha256 d12120d4…；含 V3-V7+Pro 档+合规空壳 KB）+ 平台环境变量（网关 `.tsecbench.gw` 规则、`ASTRA_KB_DISABLED=1`、`DSH_PRO_MODEL=deepseek-v4-pro`）。
- **合规红线**：平台规则禁止内置题目历史记忆——镜像物理空壳 KB + 运行时开关双保险；密钥只走环境变量，绝不入镜像/git（dist/ 已 ignore）。

## 九、深度安全审计第二轮（2026-08-27）

三路并行审计（服务端API安全 / 调度器逻辑闭合 / Runner数据操作），发现并修复：

**安全加固**（服务端暴露场景）：
- API-Key 认证中间件（ASTRA_AUTH_TOKEN 环境变量启用，覆盖全部路由）
- PUT /settings 加上限（防 intent_timeout 劫持瘫痪全服务）
- 所有 str 字段加 max_length / archive 分批（防 OOM / SQL 变量溢出）
- kind 字段 Literal 枚举 / 生产禁用 /docs /openapi.json
- 409 响应去 claimer 名（防 worker 身份枚举）

**调度器核心修复**：
- D1: runtime_project_ids 只增不减 → max_running_projects 饿死新项目（reap 时移除）
- D2: reason 审查后写图前不查租约 → 双重写图（写前复查 lease.failure）
- D3: 心跳线程裸 json() → 静默死亡 → 同 intent 双跑（try/except + 降级）
- D4: consolidate 归档未保护未决航向 from 引用 → 来源链断裂
- D6: archive 失败仍返回 success → 每周期叠摘要风暴
- J2: unhealthy 冷却被同批 success 清除

**Runner 核心修复**：
- D1(最严重): self_heal_restart 的 shutdown 是死代码（直接调 AstraDaemon.instance().shutdown()）
- D2: 脉搏基线从历史峰值改为上次采样值（防活跃题换血后假阳性重启）
- D3: 看门狗模块级状态跨实例残留（_reset_watchdog_state() 在 run_benchmark 入口调用）
- D4: Constellation 写入加 threading.Lock
- D5: ProgressStore 损坏时尝试 .tmp 回退
- B1: started_this_round 局部变量（防跨轮残留假 close_failed）
- B2: close 清道夫跳过活跃题（防杀正在解题的容器）
- B3: skipped_codes() 加锁
