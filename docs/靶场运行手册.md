# tsecbench 六小时靶场运行手册（ASTRA × DSH）

> 目标：拿到 `BENCHMARK_TOKEN` / `BENCHMARK_BASE_URL` + VPN 后，按本手册在 10 分钟内
> 进入满载跑分，并跑满六小时窗口不空转、不丢分、可复盘。

## 托管模式（ hosted，比赛同款跑法）

### 1. 构建并上传镜像（代码有改动后必须重新构建）

```bash
docker build -f container/Dockerfile -t astra .
docker save astra:latest | gzip > agent.tar.gz   # 平台上传，≤3GB
```

镜像内置：引擎 + dsh 舰队 + 技能库（container/.agents、AGENTS.md）+ runner
（默认即 dsh 混合舰队 / easy→hard 开题 / hint 15-30-45）。key 不打进镜像，
以平台"运行时环境变量"注入。

### 2. 平台运行时环境变量（关键：大模型网关）

托管沙箱**不通公网**——大模型 API 必须走平台网关（域名加 `.tsecbench.gw`
后缀，https 改 http），我们两家供应商均在白名单：

| 变量 | 值 |
|---|---|
| `DEEPSEEK_API_KEY` | `sk-44d8...`（主力 DS key） |
| `ZHIPU_API_KEY` | 智谱企业版 Coding Plan key |
| `DEEPSEEK_BASE_URL` | `http://api.deepseek.com.tsecbench.gw` |
| `ZHIPU_BASE_URL` | `http://open.bigmodel.cn.tsecbench.gw/api/coding/paas/v4` |
| `ASTRA_TASK_WINDOW_MINUTES`（按窗口设） | tsecbench 6h 测试可不填（默认 360）；**百度 24h 窗口必填 1380** |

- `BENCHMARK_TOKEN` / `BENCHMARK_BASE_URL` 由平台自动注入，**不要手动填**。
- 双 key + 双网关 URL 齐备 → 引擎自动渲染 4 worker 混合舰队（DS 探索×3 +
  GLM 探索×2 + GLM 决策×2 + DS 兜底×2）。
- watchdog 同样读这两个 BASE_URL 变量，行为一致。
- 若某次想退回单模型：加 `ASTRA_MIX_PROVIDERS=0`（仅 DS 舰队）。

### 3. 跑前验证顺序

1. 本地先过一遍 `--check`（见下文 §2）确认 `[PASS] 模型舰队 = dsh 混合`
2. 托管跑一次短窗口验证：网关连通、GLM/DS 双通道出 token、f/b 系列题目真的进队列
3. 看跑分详情页：base_model 应显示 deepseek-v4-flash + glm-5.3 双模型

### 4. 与本地模式的差异对照

| 项 | 本地模式 | 托管模式 |
|---|---|---|
| 模型 API | 公网直连（https） | 平台网关（http + .tsecbench.gw） |
| 平台访问 | 需 VPN + 手动 token | 平台自动注入 |
| 运行位置 | 本机 docker/local | 平台 8核16G 沙箱（结束即销毁） |
| 交付物 | 无需镜像 | agent.tar.gz（≤3GB，启动即自动开跑） |

## 0. 环境准备（首次，本地模式）

```powershell
# Windows：一键准备 dsh CLI + runner 复制 + patch 校验 + headless boot 自检
powershell -ExecutionPolicy Bypass -File scripts\setup_dsh.ps1
```

## 1. 连接 VPN（本地模式专用）

- 使用平台下发的 `.ovpn` 配置文件（本仓库根目录已有 `task_coLqTxKz1SQg_vpn_config.ovpn`）。
- 连接后确认：`ping <平台域名>` 通；`154.17.18.252`（旧代理）不再需要，Kimi/DeepSeek 走公网。

## 2. 自检（接 token 后第一步）

```bash
# 设置环境变量后先跑自检：平台 API 连通 / 模型 CLI / DSH patch / 引擎可启动
# 双 key 注入 = 混合舰队（DS 探索 + GLM 探索/决策 + DS 兜底，4 worker 自动渲染）
BENCHMARK_TOKEN=xxx BENCHMARK_BASE_URL=https://... ASTRA_WORKER_TYPE=dsh \
DEEPSEEK_API_KEY=sk-44d8... ZHIPU_API_KEY=<GLM key> \
  python container/astra_runner/runner.py --check
```

`[PASS]` 全部通过即可开跑；任一 `[FAIL]` 会给出修复提示。

## 3. 正式开跑（六小时）

```bash
BENCHMARK_TOKEN=xxx BENCHMARK_BASE_URL=https://... ASTRA_WORKER_TYPE=dsh \
DEEPSEEK_API_KEY=sk-44d8... ZHIPU_API_KEY=<GLM key> \
python container/astra_runner/runner.py --progress-file %TEMP%\astra-progress.json --watchdog
# 分级 hint 默认即生效：15 分钟第 1 次 / 30 分钟第 2 次 / 45 分钟无果保留进度放回队尾
# （--hint-after-seconds 900 --hint2-after-seconds 1800 --defer-after-seconds 2700）
```

内置行为（无需额外配置）：
| 能力 | 说明 |
|---|---|
| 并发满载 | `--parallel auto`：探测平台名额上限（3）并保持满载 |
| 六小时窗口 | `--task-window-minutes 360`：剩余不足最长单题（45min+收尾）停止开新题 |
| 断点续跑 | 每题 start/关题落盘进度文件；崩溃重启自动跳过已尝试题 |
| 自动 hint | 卡题半程无 flag → 取平台 hint 注入 ASTRA 项目（`--no-auto-hint` 关闭） |
| flag 即提 | 星图发现 flag 立即提交（幂等 DuplicateSubmit 跳过） |
| 不可达保护 | SDK 调用指数退避重试，连续失败 ERROR 告警"可能 VPN 断开" |
| 成本量化 | 报告输出 `total_tokens`（input/output/cache_read/cache_write/reasoning） |
| 首次 flag 时长 | 报告输出 `first_flag_seconds`（评审"单高危漏洞发现时长"口径） |

## 4. 运行监控

- **崩溃自愈**：`astra_supervisor.sh`（引擎）+ `runner_supervisor.sh`（runner，rc=0 停止、
  连续失败退避 300s）双监督器自动拉起。
- **日志**：`%TEMP%/astra-engine-*.log`（引擎，轮转保留 10 份）、`astra-runner-*.log`（runner）。
- **VPN 断连**：runner 会打 ERROR 告警；连续失败 3 次 supervisor 退避等待（不疯狂重启）。

## 5. 任务到期 / 复盘

- 平台到期（`already finished` 409）→ runner 自动停止，输出 JSON 报告。
- 报告字段：每题 `flags_correct/awarded/elapsed_seconds/first_flag_seconds/used_hint/
  facts_count/hints_count/error` + 汇总 `total_awarded/total_flags_correct/total_tokens`。
- 复盘要点：hard 题超时归因（星记数/失败学习 hints）、token 成本（效能美学）、
  首次 flag 时长分布。

## 常见问题

| 现象 | 处理 |
|---|---|
| `--check` 平台 API `[FAIL]` | 检查 BENCHMARK_BASE_URL/token、VPN 是否已连 |
| dsh MISSING_CREDENTIAL | anthropic 模式缺 `ANTHROPIC_AUTH_TOKEN`；deepseek 模式缺 `DEEPSEEK_API_KEY` |
| `resume failed ... starting a fresh session` | execute 超时被杀未落盘 → 自动同 id 创建/回退，能力降级不断链 |
| 重启后从第一题重跑 | 忘了 `--progress-file`（断点续跑依赖它） |
| 镜像构建拉基础镜像失败 | Docker Desktop 镜像加速器失效：`~/.docker/daemon.json` 换可用 mirror 后重启 Docker Desktop |

## 前端接入 / 清理（重构后）

**接入点**（server 契约，`astra/src/astra/server/app.py`）：
- `GET /` → `static/index.html`（单页入口）
- `/static/*` → `static/` 目录挂载（StaticFiles）

**重构工作区**（`docs/ui-rework/`）：用户前端重构的开发验证区——测试脚本 + 迭代截图
（audit 审计 / console 控制台 / graph 图内搜索 / veil 蒙版），连 `http://127.0.0.1:8321`
（`astra serve --port 8321 --db-path <temp>`），依赖 `astra/node_modules/playwright-core` + 系统 Edge。

**接入流程**：
1. 把新前端文件放入 `astra/src/astra/server/static/`（保持 index.html 入口 + /static 引用）。
2. 自检：`python scripts/check_frontend.py`——校验 index.html 全部引用存在、`GET /` 与每个
   `/static/*` 返回 200、列出未被引用的文件（清理候选）。
3. 渲染验证（沿用 ui-rework 流程）：`astra serve --port 8321`（或复用现有 server）+
   `node docs/ui-rework/shot.js <prefix>` 截图检查；功能回归跑
   `node docs/ui-rework/func-test.js`、`graph-test.js`、`audit-test.js`、`console-test.js`
   （先 `python docs/ui-rework/seed.py` 造数据，确认 PASS 数）。
4. 清理重构前的旧文件：删除 check 脚本列出的未引用文件 + 被替换的旧 `index.html/app.css/app.js`
   （间接引用已计入——fonts.css 的 url() 与 app.js 的动态加载不会误删）。
5. 全量测试：`uv run --group dev pytest`（test_server_api 等会覆盖 server 契约）。

> 当前基线（2026-08-14 实测）：index.html 引用 8 资源全 OK、GET / 200；未引用残留
> 7 个 vendor 布局库（cola/elk/klay/tailwindcss）——新前端接入时一并清理。
> 新前端代码尚未放入 static/（重构进行中，docs/ui-rework/ 为开发验证区）。
