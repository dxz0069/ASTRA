# ASTRA 重构备忘（真实靶场联调实录 2026-08-13）

> 记录真实运行中暴露的问题与重构方向。状态：✅已修 / 🔧观察中 / 🎯重构候选。

## 已修复（本机 Windows local 模式）

1. ✅ **claude.CMD shim 破坏长 prompt**：npm 批处理包装会吞掉含换行的参数（模型只看到"# Task"标题）。修复：Windows 下直跑 `node_modules/@anthropic-ai/claude-code/bin/claude.exe`（`claudecode.py._claude_executable`）。
2. ✅ **pi.CMD 同样问题**：pi 无原生 exe，改为 node 直跑 `dist/cli.js` + prompt 写入临时文件以 `@file` 传入（`pi.py._prompt_arg`）。
3. ✅ **~/.claude/settings.json 全局污染**：用户其他项目的中转配置（模型名/API key）覆盖 worker env。修复：worker env 注入 `CLAUDE_CONFIG_DIR` + `ANTHROPIC_API_KEY`，配置完全自包含。
4. ✅ **runner 进程组级联退出**：runner 内嵌启动 server/dispatcher 时，主进程异常会带走整个进程组。修复：`ASTRA_EXTERNAL_ENGINE=1` 分离部署（server/dispatcher 独立后台，runner 只做 SDK 编排）。
5. ✅ **Windows 无 /bin/sh、MSYS2 sh 破坏含空格参数**：pi 的 sh 包装、curl 的 verbose healthcheck 全部平台分支化。
6. ✅ **YAML 反斜杠转义**：Windows 路径写入双引号 YAML 必须正斜杠（`CLAUDE_CONFIG_DIR` 等）。
7. ✅ **失败风暴**：failed 任务无冷却会无限重派，加了 15s 冷却。
8. ✅ **DeepSeek 认证头**：Anthropic 端点要 `x-api-key` 而非 `Authorization: Bearer`。

## 🎯 重构候选（重要）

1. **bootstrap 的"憋大招"模式**：bootstrap prompt 要求"持续工作直到完成才输出 JSON"，真实靶场下 claude 跑满 300s 超时、零输出，只靠 conclude fallback（90s）收尾——**中间产物全部丢失**（模型探索过程在 session 里但没沉淀）。
   → 重构：bootstrap/explore 采用**增量星记**模式（阶段结论就写回，而不是最后憋一个）；或 bootstrap 超时后复用 session 用 conclude 前先做一次中间 dump。
2. **flag 传递链路脆弱**：flag 依赖 agent 主动写回星图描述；若 agent 把 flag 写在文件里（AGENTS.md 允许放文件），runner 收不到。→ 重构：runner 增加"工作区文件扫描"兜底（正则扫 workspace 内文件）；或 skill 强化"flag 必须写回星图"。
3. **Windows local 模式的整体健壮性**：本轮修了 8 个 Windows 专属坑（.CMD/路径/编码/进程组），说明 `container/Dockerfile` 的 Linux 路径才是主场；本机联调建议用 Docker 模式（构建镜像）减少平台差异。→ 重构：提供 Windows 联调一键脚本（自动注入所有 env/隔离配置）。
4. **双星审查只审 reason 提案**：explore 的 fact 未过 challenge（低置信直接写）。→ 重构：低置信（confidence=low）fact 触发 challenge 审查。
5. **runner 报告粒度**：现在只有每题汇总，缺"首次 flag 时间/无效尝试数"。→ 重构：从星图时间线提取子任务粒度指标（AutoPenBench 风格）。
6. **超时策略**：bootstrap 300s / conclude 90s 是经验值，真实模型下 bootstrap 几乎必超时。→ 重构：按题类型（easy/hard）自适应超时；conclude 前先中间 dump。
7. **引擎日志**：dispatcher/server 日志已落文件（`%TEMP%/astra-engine.log`），但无日志轮转；长跑 6 小时会膨胀。→ 重构：日志轮转 + 结构化指标（token 消耗/每次调用耗时）喂评审量化。
8. **e1-01 实测观察**：模型在 bootstrap 里做了大量有效侦察（WAF 指纹、JSON/multipart 绕过测试）但超时丢失——**证实候选 1 是最大效率损失点**。
9. **pi 的 healthcheck 返回 session 事件流**，startup 日志里不算"HTTP 状态"——语义混淆（HTTP=-）。→ 重构：healthcheck 输出契约统一。
10. **runner flag 轮询依赖 `engine.stats()`**：FakeEngine 与真实引擎行为差异（getattr 容错）——可接受但脆。
