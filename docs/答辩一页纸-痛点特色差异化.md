# ASTRA 答辩一页纸：痛点 · 特色 · 差异化

> 现场答辩用核心话术。全部基于真实代码与实测，不提 Cairn、不上分数名次。

## 一、我们解决的真实痛点（开口第一段）

**痛点一句话：当前所有安全 Agent 都是"金鱼"——单次任务内上下文爆了就失忆，跨任务经验归零，跑一百次和跑一次一样笨。**

拆成三个具体问题：
1. **上下文失忆**：长程渗透任务动辄数百条发现，全塞 prompt 既贵又互相覆盖，关键信息被闲聊淹没；
2. **跨会话失忆**：上一场解过的题型，下一场从零开始，人类红队的"手感"无法积累；
3. **经验靠人搬**：即便有复盘，也是赛后人工读日志、人工写文档，规模化即失效。

## 二、我们的核心方案：星尘记忆——四层分级记忆 + 经验复利闭环

仿生人类记忆的认知科学结构（多存储模型/Baddeley 工作记忆/加工水平理论/海马巩固），落在工程上：

| 层 | 机制 | 代码落点 |
|---|---|---|
| L1 瞬时记忆 | worker 会话原始上下文，token 预算硬上限 | worker CLI 会话 |
| L2 工作记忆 | 焦点子图裁剪：相关度×时间近度打分，只内联最相关星记，完整星图走文件引用，**零上下文膨胀** | `dispatcher/context.py` |
| L3 短时记忆 | 星图事实库（SQLite）+ Epitome 摘要压缩：旧事实自动蒸馏为摘要星记 | `tasks/consolidate.py` |
| L4 长时记忆 | 解题攻击链自动沉淀 → 脱敏 → 固化知识库 → 下轮开局按题注入 | `knowledge/challenge-approaches.md` |

**升级后的三件"进化机制"（本轮新增，演示可讲）**：
1. **语义召回**：星记检索从纯词面匹配升级为 词面+语义向量 混合打分（`embeddings.py`，API/本地模型双通道，失败自动降级）——"SQL 注入的教训"现在召得回 "MySQL 注入"；
2. **回忆强化**：每条历史思路带实战战绩注入（"该思路历史战绩：3 次命中/0 次未命中"），命中自动加权（`memory-stats.json`）；
3. **遗忘曲线**：长期未命中条目自然沉底，知识库向高频有效打法自动收敛。

## 三、与同类产品的差异化（被问"和 XX 比呢"时用）

- **对比 XBOW/商用渗透 Agent**：它们的知识是静态注入的专家规则；ASTRA 的知识是**每场比赛自动生长的**。XBOW 强在单兵能力，我们强在**经验复利**——同一系统第 100 道题比第 1 道题强，这是机制差异不是调参差异。
- **对比 Mem0/Zep/Letta 等记忆框架**：它们是通用记忆中间件，不懂安全场景的"什么值得记"；ASTRA 的记忆对象是攻击链（入口→漏洞→利用），记忆单元本身就是渗透语义。
- **对比开源 CAI 等 agent 框架**：框架解决"怎么调工具"，我们解决"怎么记住打过的仗"——四层记忆 + 星图状态空间是调度层之上的认知层。

## 四、可信度锚点（有据可查）

- 多轮实测迭代，每轮赛后复盘蒸馏出题型模式库（AGENTS.md 实战标注来源与日期）；
- 对抗式质询机制：关键提案需独立"质询星探"批判通过才入星图，防方向漂移；
- 全链路脱敏红线：知识库不含也不猜 flag 值，双层脱敏（flag 值 + secret 语境随机串）；
- `astra memory stats` 命令可现场展示四层记忆全景与复利统计。

## 五、一句话收尾

**"别人做的是更强的单次 agent，我们做的是会变强的 agent 系统——记忆是我们和所有竞品之间最深的护城河。"**
