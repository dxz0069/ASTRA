## 一、项目概述

ASTRA 是一套面向 AI 攻防全链路的状态空间搜索与决策引擎。它不预设角色与工作流，只维护一张 **FGS 图（Fact–Goal–Step Graph）**：给定起点（Origin）与目标（Goal），引擎在未知状态空间中持续搜索可行路径——漏洞挖掘、渗透测试、靶场闯关只是它已证明的第一片星域。

与「把提示词写得更小心」的常规方案不同，ASTRA 把可靠性建立在运行时机制上：状态全部外化为图、决策干净上下文、写入自证确认、死路留痕账本。模型负责理解、推理与生成，引擎负责把模型接入真实目标、真实工具与真实验证。

## 二、总体架构

ASTRA 由三层构成：

1. **FGS 图核心**：状态空间的外置化账本，append-only，五种原语：
   - 事实（Fact）：一条已确认的客观发现（漏洞、端口、凭据、flag；负结果同样是事实）；
   - 目标（Goal）：项目的完成条件 = 搜索的终止条件，可挂动态子目标（SubGoal）；
   - 步骤（Step）：从既有事实出发、预期产出新事实的因果行动——每条步骤必须声明「预期产出什么」，可被决策关闭并留痕（死路账本，防重开）；
   - 发现（Finding）：搜索过程的沿途产出（如漏洞），与终点相对的一等公民；
   - 指引（Hint）：任意时刻注入的判断（人类或系统），作为风险提示进入后续推理。

2. **双活动调度（Decide & Execute）**：引擎只有两类活动，是同一个运行器注入不同提示词与工具的实例，而非固定角色子智能体——
   - **Decide（决策）**：串行、事件触发（任务开始或图变化）、每次从干净上下文起跑（无历史对话，决策成本只与图规模相关）；只拥有图操作权限——判定 Goal 达成、新增步骤、关闭失效步骤、增删子目标；
   - **Execute（执行）**：并发多实例；拥有世界工具（read/bash/edit/write）与唯一的 `submit_fact` 入图闸口——确认责任在执行者自证：跑过命令、亲眼看到输出才写回，可携一条沿途 Finding。

3. **执行底座（pi 舰队）**：接入大模型 CLI（DeepSeek / GLM 的 Anthropic 兼容端点，底座为 pi-coding-agent），支持 Docker 与 local 双执行模式；local 模式以宿主进程运行，适配托管平台与离线环境。

全流程自动化由 `astra-runner` 编排器完成：它连接评测平台（TSecBench），完成题目容器的启动/关闭、为每题创建 ASTRA 项目、从图收集 flag 统一提交（幂等）、输出每题得分与耗时报告——从题目下发到成绩回收全程无人值守。

## 三、核心机制

### 3.1 焦点上下文：预算治理的读侧裁剪

传统 Agent 把整张图的历史无差别塞进每次推理，token 随图线性膨胀。ASTRA 做预算治理：

- **焦点子图（Focus）**：每次推理只内联与当前目标/步骤最相关的事实与步骤（相关度 × 语义召回 × 时间近度 × 图距加成，凭据级关键事实钉住保底），受 `context_budget` 硬上限约束；完整图仅以文件引用保留，按需读取；
- **零膨胀保证**：内联量恒有硬上限，不随图规模增长（端到端测试断言）。图本身 append-only 不压缩——历史完整可审计，膨胀由读侧裁剪吸收。

效果：长任务上下文稳定，单题推理成本可控，模型注意力集中在当前决策链。

### 3.2 写入自证与死路账本

图是唯一事实账本，写入纪律由两道机制保证：

- **submit_fact 自证**：事实的确认责任在执行者——只有亲自执行过命令并看到输出才允许写回；错误的提交在「错交不扣分」的赛制下期望损失极小，因此引擎不再设独立审查环（实测对抗式审查在错交免费场景下期望收益为负）；
- **步骤生命周期账本**：每条步骤带「预期产出」声明（可验收），决策可关闭失效步骤并强制留痕（close_reason）；关闭的方向不允许作为新步骤重开——配合负结果事实的焦点保活，形成双账本防重复探索。

### 3.3 失败学习与验证边界

- **失败学习**：命令失败、解析失败等真实失败被脱敏后沉淀为指引（风险提示），注入后续推理轮次——教训只作风险提示，绝不充当完成证据，防止「记住失败」被误当「验证成功」；
- **验证边界**：flag 正确性以平台提交返回为准（`correct/awarded`），图内推断与平台验证严格分离；平台回执写回为事实，作为下一轮决策的真实见证。

### 3.4 无效尝试抑制

行业基准（Cybench：GPT-4 agent 仅完成 3/15 且时间大量耗在侦察与无效尝试；AutoPenBench：202+ 挑战平均完成约 27%，最弱环节是"判断何时停止"）表明：自主 agent 的瓶颈不在能力而在**路线纪律**。ASTRA 的应对：

- 失败指引标记的方向不得重复提案；决策显式评估每条开放步骤的投入产出（派发次数 × 产出事实数），低产步骤关闭换向；
- 死路账本（关闭步骤 + 负结果事实）让"已排除"成为可查阅的资产而非记忆负担。

### 3.5 混合模型舰队与托管适配

- **DS+GLM 混合舰队**：执行位（首探/Execute）由 DeepSeek v4 Flash 承担——吞吐高、工具调用稳定；决策位（Decide）由 GLM-5.3 承担——低频高价值场景吃深度推理红利。同图 Decide 由服务端租约强制串行（同一张图同时只有一个决策者），跨图可并行；执行位多实例并发（快攻 + 多路并进）；
- **Docker 模式**：执行器 CLI 在每项目容器中执行，隔离环境、工具完备（Kali 工具链 + nuclei/impacket/cloudfox 等）；
- **local 模式**：宿主进程直接执行，无需 Docker；托管平台受限环境下以该模式运行，镜像内置完整引擎，`astra-runner` 作为默认入口自启动，大模型 API 经平台网关访问。

### 3.6 稳定性工程（6 小时无人值守的工程保障）

- **开题策略**：价值排序开题（easy 热身分值降序 + 其余全分值降序），杜绝低分题被排队饿死（实测教训：一轮因原始顺序 8200 分难题未开题）；
- **分级 hint**：卡题 15/30 分钟自动取平台提示、超时保留进度放回队尾（defer 预算随旗数/难度弹性），避免死磕单题拖垮吞吐；多旗题部分旗不关题，回队续攻；
- **断点续跑**：每题 start/关题落盘进度文件，崩溃重启自动跳过已完成题；
- **模型 watchdog**：端点探活 + 会话错误扫描（盯 pi 会话目录），配额耗尽秒级告警；四层自愈（网络退避/容器清道夫/全停看门狗/半死看门狗）保障长窗口满载；
- **全程可审计**：每题输出事实数/步骤数/发现数/指引数/耗时/得分/token 消耗与首 flag 时长。

## 六、创新点总结

1. **FGS 图 + 双活动架构**：状态全部外化为 append-only 的 Fact–Goal–Step 图（含 Finding/SubGoal），Decide 串行干净上下文、Execute 并发自证写入——结构对齐状态空间搜索的本质，工程上极简（无审查环、无压缩机械）；
2. **Finding 沿途发现**：把「搜索过程的产出」（漏洞）提为一等公民，与「搜索终点」（Goal）分离——对齐渗透测试与代码审计的真实交付物；
3. **步骤契约与死路账本**：每条步骤必附预期产出（可验收），关闭必留痕——无效尝试这一行业最大耗时源有了结构性抑制；
4. **赛制经济学层**：价值排序开题、defer 预算、hint 购买门控、多旗收割与平台回执入图——把评测规则吃透为代码的整层能力；
5. **混合模型舰队**：执行与决策分治——吞吐型模型铺量、深度推理模型攻坚，同图决策串行跨图并行，故障自动回退；
6. **全链路自动化 + 双模式弹性**：从题目下发、探索、flag 收集提交到成绩报告全程无人值守；一套引擎同时适配容器隔离与受限托管环境。
