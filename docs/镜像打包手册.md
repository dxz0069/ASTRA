# ASTRA 托管镜像打包手册（v7 定稿，2026-08-28）

> 目的：把 v5/v6/v7 三轮打包踩过的所有坑沉淀成标准流程，照做即可，减少重试。
> 平台硬约束：**上传 ≤3GB** + **必须是 OCI 格式**（`oci-layout`/`index.json` 缺一被拒）。

## 一、完整流程（六步，按序执行）

### 1. 增量构建分层镜像

```bash
cd /e/study/项目/Cairn-main
docker build -f container/Dockerfile.slim -t astra-slim:vN .
```

- 构建上下文快照 1-2 分钟属正常（`.dockerignore` 已排除 .git/dist/tmp/docs/.venv）；
  **改了引擎代码（container/astra_runner/）必须重建**——COPY 层之后的层重建很快，
  但 npm/apt 层变更会触发其后所有层重跑（小时级，耐心等）。
- Windows 下如遇路径类报错先加 `MSYS_NO_PATHCONV=1`。

### 2. 容器内验证清单（不通过不进入下一步）

```bash
# ① CLI 就位
docker run --rm --entrypoint sh astra-slim:vN -c \
  "which claude && claude --version; which dsh || echo 'dsh absent OK'"
# ② 引擎渲染烟测（3 worker + MCP 注入到 .claude.json）
docker run --rm --entrypoint sh \
  -e ANTHROPIC_AUTH_TOKEN=sk-smoke -e ANTHROPIC_MODEL=deepseek-v4-flash \
  -e ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic \
  astra-slim:vN -c "python3 -c \"
import sys; sys.path.insert(0,'/opt/astra-runner')
from astra_runner_engine import AstraDaemon
t = AstraDaemon()._render_dispatch_config().read_text()
assert t.count('type: \\\"claudecode\\\"')==3
import re,json
m=re.search(r'CLAUDE_CONFIG_DIR: \\\"([^\\\"]+)\\\"',t)
assert json.load(open(m.group(1)+'/.claude.json'))['mcpServers']['playwright']['command']=='playwright-mcp'
print('ENGINE SMOKE OK')\""
# ③ 全链路真打模型（真实 key；返回 pong 才算通）
docker run --rm --entrypoint sh \
  -e ANTHROPIC_AUTH_TOKEN=sk-真key -e ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic \
  -e ANTHROPIC_MODEL=deepseek-v4-flash -e ANTHROPIC_SMALL_FAST_MODEL=deepseek-v4-flash \
  -e CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 \
  astra-slim:vN -c "timeout 90 claude --dangerously-skip-permissions -p 'Reply with exactly pong.'"
```

**坑 1：镜像内二进制名必须实测**。v7 把 MCP 写成 `mcp-server-playwright`，镜像里实际是
`playwright-mcp`（`@playwright/mcp` 的 bin 字段决定）——③ 和上面的断言就是防这类"文档想象名"。

### 3. 扁平化（docker export | import）

```bash
cid=$(docker create astra-slim:vN)
docker export "$cid" | docker import \
  --change 'ENTRYPOINT ["python3","/opt/astra-runner/runner.py"]' \
  --change 'ENV PATH=/home/kali/.local/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin' \
  --change 'ENV LANG=C.UTF-8' \
  --change 'ENV TZ=Asia/Shanghai' \
  --change 'ENV PLAYWRIGHT_MCP_BROWSER=chromium' \
  --change 'ENV CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1' \
  --change 'ENV PYTHONUNBUFFERED=1' \
  --change 'USER kali' \
  --change 'WORKDIR /home/kali/workspace' \
  - astra-flat:vN
docker rm "$cid"
docker images astra-flat:vN --format "{{.Size}}"   # 预期 ~9.7G（裸文件系统）
```

**坑 2：`docker export` 只认容器不认镜像**。直接 `docker export astra-slim:vN` 会报
"No such container"并产出 5KB 空镜像——必须先 `docker create` 拿容器 ID。
**坑 3：export|import 丢全部运行配置**。ENTRYPOINT/ENV/USER/WORKDIR 必须用 `--change`
逐项补回（上面 9 条就是全套，缺一条容器行为就变，比如少了 USER=kali 会以 root 跑）。
**坑 4：分层镜像里 rm/upx 只是白注销**。瘦身（删包/UPX）若在分层内做，OCI tar 只会更大
（v6 实测 3.4G→3.6G）——一切瘦身要么进 Dockerfile 层内（重建层），要么扁平化后做。

### 4. OCI 导出（gzip level 9）

```bash
mkdir -p tmp/oci-export && echo "FROM astra-flat:vN" > tmp/oci-export/Dockerfile
docker buildx build --platform linux/amd64 \
  -f tmp/oci-export/Dockerfile tmp/oci-export \
  --output type=oci,compression=gzip,compression-level=9,dest=dist/app_dist_vN.tar
```

**坑 5：不能 `echo FROM xxx | buildx -f -`**——stdin 同时当 build context 和 dockerfile 直接报
"can't use stdin for both"；用临时 Dockerfile + 目录上下文（`tmp/` 已在 .dockerignore，
产物不会反过来污染后续构建）。
基线数据：v6 扁平 9.75G → tar 2.65GiB（压缩率 ~27%）；v7 扁平 9.73G（dsh 移除≈claude 214M
加入，持平），预期 tar 同量级，3G 限内。

### 5. 产物验收（四查）

```bash
tar -tf dist/app_dist_vN.tar | grep -E "oci-layout|^index.json"   # ① OCI 结构在
ls -la dist/app_dist_vN.tar                                        # ② ≤3G
docker load -i dist/app_dist_vN.tar && docker run --rm --entrypoint sh astra-flat:vN -c "claude --version"  # ③ 可回载可跑
sha256sum dist/app_dist_vN.tar > dist/app_dist_vN.tar.sha256      # ④ 记录指纹
```

**坑 6：tar 正在写入时别 `tar -tf`**（EOF 假错误）；等命令完全退出再验。

### 6. 上传前部署模拟 + 平台侧（上传后）

**上传前最后一查**（部署超时事故的教训：平台先起容器后注 env，runner 若秒退会陷入
重启循环→部署探测永远等不到存活）：

```bash
docker run -d --name deploy-probe astra-flat:vN && sleep 45 && docker ps --filter name=deploy-probe
# 仍 running = 通过（runner 在等凭证注入，不退出）；Exited = 打回第 2 步排查
docker rm -f deploy-probe
```

- 平台先起容器**后**注入 env——runner 已有凭证等待循环（`ASTRA_CRED_WAIT_SECONDS=900`），
  不会秒退；但 900s 内 env 没到就是平台问题，看任务日志确认。
- `dist/hosted.env` 用"从 .env 导入"整包灌入；**文件必须 LF 行尾**（CRLF 会毒化 token 值）。
- 开局 3-5 分钟看健康检查：网关路径 `api.deepseek.com.tsecbench.gw/anthropic` 若不通，
  startup healthcheck 立即报错（这是我们选的行为：秒炸优于 40 分钟静默空转）。
- 首得分健康基线：**前十名 0.7-3.5 分钟首得分**（见 docs/Tsecbench前十名日志机制拆解.md §1）；
  超过 10 分钟零得分即判管道异常，中止排查，不空烧 6 小时窗口。

## 一·五、标签纪律（2026-08-29 新坑）

**`astra-slim:v5s` 不是"旧版本"，是 Dockerfile.slim 多阶段构建的 pinned-bins 工件源**
（`FROM astra-slim:v5s AS pinned-bins`，从中 COPY 二进制/知识库/工具/PoC）——删了它构建直接断
（还可能被 docker mirror 403 误导成网络问题）。清理"旧镜像"前先看 Dockerfile 的 FROM 引用。
工件源可随时用最新镜像重打：`docker tag astra-slim:v7 astra-slim:v5s`。

## 二、构建环境坑（Windows/GitBash 专供）

| 坑 | 对策 |
|---|---|
| MSYS 路径改写（`-e HOME=/x` → `C:/Program Files/Git/x`） | 命令前缀 `MSYS_NO_PATHCONV=1` |
| apt 源被包升级复活成 neusoft 重定向轮盘 | 工具层安装前重新钉 sources.list（Dockerfile 已内置） |
| 清华 HTTPS 镜像握手失败 | 勿用；npm 用 npmmirror，pip 用 tuna/aliyun 双源 |
| pip `for i in 1 2 3; do cmd && break; done` 吞失败（返回 sleep 的 0） | 硬失败模式：`ok=""; ...; [ -n "$ok" ]`（Dockerfile 已内置，改命令时保持） |
| apt purge 带通配名、不存在项整批中止被 `|| true` 吞 | 先 dpkg query 实名再 purge（v6 的 OpenCL 776M 事件） |
| Defender 锁"安全内容文件"导致 COPY 偶发失败 | 重跑即可；构建前关闭实时防护更稳 |
| Windows python 在仓库 cwd 下 PYTHONHOME 混乱 | 一律用 `astra/.venv/Scripts/python.exe` |
| heredoc 里 `\\n` 被转义层吃成真换行（两次事故） | 生成代码避免反斜杠转义：用 Edit 工具或 `chr(10)` |

## 三、版本对齐纪律

1. **镜像内代码 = 仓库当前代码**：改了 `container/astra_runner/` 或 prompts 后没重建
   slim，镜像里还是旧的（v7 的 playwright-mcp 修复就重蹈了一次）。
2. 每次镜像定版打 tag 记 sha256，与上传记录一一对应；回退=传回上一个 tar，
   不允许"用旧 tar + 新 env"混搭（栈不匹配）。
3. 当前基线：`astra-slim:v7` + `astra-flat:v7`（claudecode 栈）；v6 兜底包
   `dist/app_dist.tar`（dsh 栈，2.65G）——v7 验证通过前勿删。
