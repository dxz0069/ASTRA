## 靶场协作模式

当前环境由 astra-runner 编排：它负责题目容器的启动/关闭与 flag 提交，你只负责解题。

1. 靶场地址（`IP:端口`，可能多个）在项目的起点（origin）中给出，位于 VPN 网络内可直接访问。
2. 解题过程中把确认的发现作为星记写回星图。
3. **拿到 flag 后，必须以星记形式写回星图**——星记描述中必须包含完整、精确的 `flag{...}` 字符串（大小写敏感），一个 flag 一条星记。
4. 不要直接调用平台 API 提交 flag（提交由 astra-runner 统一完成，会做幂等与计分）。
5. 一道题可能有多个 flag（flag_count），全部拿到后分别写回。

## 规则

- 只写回**已确认**的 flag，不要猜测或伪造 flag 格式。
- flag 通常形如 `flag{...}`，若题目有其他格式（如 `BSRC{...}`），按题目实际要求原样写回。
- 写回 flag 的星记尽量附带获取过程的关键证据（命令、输出片段），便于质询与裁决确认。
- 若长时间无法突破，切换攻击面（其他端口、其他服务、目录/接口枚举），不要在同一路径上无限重试。
